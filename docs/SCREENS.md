# SCREENS.md — マジスケ 画面実装の指示書

> AI コーディングエージェント向け。**画面（見た目・レイアウト・UI の振る舞い）だけ** を扱う。
> DB・ルール判定・API・出力ファイルの中身は `AGENTS.md`（`CLAUDE.md`）に従うこと。両者が食い違ったら、ロジックは AGENTS.md、見た目はこのファイルを優先する。
> デザインモック：https://claude.ai/artifact/K1hUHqRCSLknKmmzfoVKgP（チームボード／ガント／WBS編集／タスク編集／週次レポートの5画面）

---

## 1. デザインの方針

- 雰囲気は「やわらかく、整理された、紙の手帳っぽいシンプルさ」。丸み・余白・少ない色。
- **色はプロジェクトを見分けるために使う**。装飾のための色は使わない。
- 1画面で「誰が・いま何を・遅れてないか」が分かることを最優先にする。
- 使わないもの：グラデーション、影の重ね、絵文字、左だけ色付きの枠線カード、ガラス風の透過。

- 状態は色だけで伝えない。必ず「遅れ」「困りごとあり」などの文字ラベルを添える。

### 文字

| 用途 | フォント | サイズ / 太さ |
| --- | --- | --- |
| 画面タイトル（h1） | Zen Maru Gothic | 32px / 700 |
| ロゴ・カード内の大見出し | Zen Maru Gothic | 18–22px / 700 |
| セクション見出し（h2） | Noto Sans JP | 16–17px / 700 |
| 本文 | Noto Sans JP | 14–15px / 400–500 |
| 補足・ラベル | Noto Sans JP | 12–13px |
| ファイル名・テンプレート | JetBrains Mono | 13px |

- `next/font/google` で読み込む。11px 未満の文字は使わない。

### 形・余白

- 角丸：カード `24px`、モーダル `28px`、アイコンタイル（大 44px）`14px`、（小 24–32px）`8–10px`、入力欄・ボタン `12px`、ピル `999px`。
- 余白は 4 の倍数。カード内 `20–24px`、カード同士 `16–20px`、ページ `32px 40px`。
- 枠は 1px `border`。影は付けない。

### アイコン

- `lucide-react` を使う（線のアイコン、`strokeWidth={2}`、20px）。絵文字は使わない。
- プロジェクトのアイコンタイルは、プロジェクト色の角丸四角に白い線アイコン。アイコンはプロジェクト作成時に選ぶ（既定：カレンダー）。

## 3. 共通レイアウト

```
┌────────────┬──────────────────────────────────────┐
│ サイドバー  │ ヘッダー（小見出し＋h1／右に操作）      │
│ 248px      │ 本文                                   │
└────────────┴──────────────────────────────────────┘
```

- サイドバー：ロゴ（タイル＋「マジスケ」＋小さく `mergecalschedule`）／ナビ（チームボード・ガントチャート・WBS編集・週次レポート）／プロジェクト一覧（色ドット＋名前＋右に締切日）／「＋ プロジェクトを作る」。
- 選択中のナビは `primary-soft` の背景＋太字＋`aria-current="page"`。
- 本文は `flex: 999 1 560px; min-width: 0`。サイドバーは `flex-wrap` で、**幅 768px 未満では上に積む**（固定・sticky・`100vh` にしない）。
- ヘッダーの小見出しは「プロジェクト色ドット・プロジェクト名・締切・予備日数」か「日付（11月19日（木））」。

## 4. 共通コンポーネント

`src/components/ui/`（shadcn/ui ベース）と `src/components/common/` に置き、画面ごとに作り直さない。

| コンポーネント | 仕様 |
| --- | --- |
| `ProjectTile` | 44px（`size="lg"`）／28px（`sm`）。プロジェクト色の背景＋白アイコン。`sm` は `tint` 背景＋2px の色枠でも可（「つぎ」の表示用） |
| `StatusPill` | `status: "ok" \| "late" \| "help" \| "free"`。状態の色の組＋文字。12px 太字、ピル型 |
| `ProgressBar` | 高さ 6–8px、背景 `#EDEEF1`、中身はプロジェクト色。右に `xx%`（太字 12px） |
| `MemberAvatar` | 円、イニシャル1文字。背景はいまのタスクのプロジェクトの `tint`（タスクなしは `#EDEEF1`） |

| `PrimaryButton` / `SecondaryButton` | 高さ 44px 以上。主は `primary` 塗り・白字・太字、副は白地＋`border-strong` |

## 5. 画面ごとの仕様

### 5-1. チームボード `/board`（ログイン後の初期画面）

- ヘッダー：日付＋h1「今日のチーム」。右に集計ピル「困りごと n」「遅れ n」「空き n」。
- フィルタ：ピル型の切替ボタン「すべて／各プロジェクト」。選択中は黒塗り白字、`aria-pressed`。
- カード一覧：`grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))`、gap 20px。
- **並び順：困りごとあり → 遅れ → 順調 → 空き**。同じ状態の中では名前順。
- メンバーカード（上から）：
  1. アバター・名前・役割（自分は「あなた · PM」）・右端に `StatusPill`。
  2. **縦タイムライン**：左列に「いま」の `ProjectTile`(lg) → 点線（2px dotted `#C9CBD2`）→「つぎ」の `ProjectTile`(sm)。右列に対応する内容。
     - いま：`色ドット いま · プロジェクト名 · 期間` → タスク名（太字 15px）→「成果物：…」→ `ProgressBar` →「終了予定まで あとn稼働日」／「予定より 約n日 遅れ」。
     - いまのタスクがない：点線枠の空タイル＋「今日は担当タスクなし」＋「11/20〜11/28 は空いています」。
     - つぎ：`つぎ · プロジェクト名 · 期間` → タスク名。
  3. 困りごとがあれば赤系の箱：アイコン＋本文＋「手を貸す」ボタン。
  4. 自分のカードだけ：「進捗を更新」（主）「困りごとを出す」（副）。
- カードを押すと、そのメンバーの担当タスク一覧（シンプルなリスト）を開く。

### 5-2. ガントチャート `/projects/[id]/gantt`

- ヘッダー：プロジェクト情報＋h1。右に「進捗管理日」セレクト、R4 の状態ピル（OK：青「最終タスク 12/3 終了 · 予備を確保」／NG：オレンジ「予備が n 稼働日足りません」）。
- 凡例：予定・進捗・イナズマ線・土日祝。
- 本体（白カード、横スクロール可）：
  - 左 360px：WBS（目的は見出し行、フェーズ行は `#FAFAFB` 背景で太字、タスク行は字下げ）＋担当＋進捗%。
  - 右：1日1列（40px）。見出しは日付＋曜日。土日祝は `OffdayBand`、祝日は曜日の代わりに「祝」。進捗管理日の列は `primary-soft`。
  - 行の高さ 48px。タスクのバーは高さ 22px・角丸 11px、予定は `tint`、進捗分を `color` で塗る。
  - 予備期間（締切 − バッファ〜締切）は斜線の帯、締切日に縦線。
- **イナズマ線**（SVG を本体に重ねる）：
  - 進捗管理日の縦線（`primary`、破線）。
  - 各タスク行の中央に点を置いてつなぐ（`#D92D20`、2.5px）。点の位置は `lib/progress` の結果を使う。
  - **完了済み（100%）と未着手（開始日が進捗管理日より後で 0%）のタスク、フェーズ行は縦線の上に置く。**
  - SVG に `role="img"` と、遅れ・先行しているタスクを文章にした `aria-label` を付ける。
- 表の下に一文で読み方を書く（「左に曲がっているタスクは遅れ、右は先行」）。
- ドラッグでの日程変更は作らない。

### 5-3. WBS編集 `/projects/[id]/wbs`

- ヘッダー：プロジェクト情報＋h1「WBS編集」。右に「＋ フェーズ」（副）「＋ タスク」（主）。
- 2カラム（`flex-wrap`）：左が WBS 本体（`flex: 999 1 640px`）、右が「ルールチェック」パネル（`flex: 1 1 280px`）。狭い画面ではパネルが下に回る。
- 目的カード：「目的」ラベル＋目的名（Zen Maru Gothic 18px）＋編集ボタン。
- フェーズごとに白カード：
  - 見出し行：並び替えハンドル・フェーズ名（h2）・「nタスク · 期間」・右に「＋ このフェーズにタスク」（`DashedAddButton`）。
  - 表（`<table>`、`min-width: 860px`、カード内で横スクロール）：タスク（小タイル＋太字）／成果物（スコープ）／担当（小アバター＋名前）／期間／稼働日／進捗（バー＋%、遅れなら「遅れ」ピル）／編集ボタン（`aria-label="○○ を編集"`、タスク編集モーダルを開く）。
  - **インライン追加行**：「＋ このフェーズにタスク」で表の末尾に下書き行（背景 `#FAFAFF`）。タスク名・成果物・担当・期間を入力。成果物が空なら枠を赤＋「成果物を入力してください」、「追加」ボタンは無効。
  - フェーズとタスクはドラッグで並び替え（`sort_order` を更新）。日付はここでは動かさない。
- ルールチェックパネル（上から R1 成果物・R2 担当者は1人・R3 並列なし・R4 バッファ・R5 進捗共有）：
  - OK は青い丸にチェック、NG はオレンジの丸に「!」。タイトル（太字 14px）＋説明（12px）。
  - 説明は具体的に書く（例：「登録済み6件はすべて入力済み。下書き1件が未入力のため追加できません」「最終タスクは 12/3 終了。締切 1/8 まで予備 5稼働日を確保」）。
- 編集できるのはプロジェクトの owner だけ。member には同じ表を読み取り専用で見せ、追加・編集ボタンを出さない。

### 5-4. タスク編集（モーダル）

- 幅 560px（スマホでは全画面）、角丸 28px、`role="dialog"`＋`aria-labelledby`。Esc と閉じるボタンで閉じる。
- 上部：プロジェクトの `ProjectTile`(lg)＋「タスクを編集」＋「プロジェクト名 · フェーズ：○○」＋閉じるボタン（`aria-label="閉じる"`）。
- 入力欄：タスク名／**成果物（スコープ）必須**（補足「分割できる最小単位で。成果物がないタスクは保存できません。」）／**担当者（1人）**のセレクト＋「メンバー分複製」ボタン／開始日・終了日（2列）。
- 日付の下に「稼働日 n日（○/○〜○/○ は土日祝のため数えない）」。日付ピッカーでは土日祝を選べなくする。
- **並列禁止（R3）に引っかかったら**：開始日の枠を赤、その下に `RuleAlert tone="error"`：
  - 見出し「○○さんはこの期間、別のタスクを担当中です」
  - 衝突しているタスクの小カード（プロジェクト色タイル・タスク名・「プロジェクト名 · 期間 · 進捗 n%」）。そのプロジェクトのメンバーでない人には「別プロジェクトの予定 · 期間」だけを見せる。
  - 「1人が同時に持てるタスクは1つまで。プロジェクトが違っても同じです。」
  - 「○/○（○）から始める」ボタン（次の空き稼働日。押すと開始日・終了日を同じ稼働日数でずらす）。
- 下部右寄せ：「キャンセル」（副）「保存」（主）。ルール違反中は保存を無効化（灰色、`aria-disabled`）。
- member が自分のタスクを開いた場合は、進捗率・実績日・成果物URL・困りごとだけ編集でき、ほかは読み取り専用。

### 5-5. 週次レポート `/projects/[id]/report`

- ヘッダー：小見出し「毎週金曜は進捗共有の日」＋h1「週次レポート」。
- 上部：「プロジェクト」「進捗管理日」のセレクト。週の最終日には「週の最終日」と添える。
- ダウンロードカード2枚（`repeat(auto-fit, minmax(300px, 1fr))`）：
  - 工程表（緑系タイル・「Excel（.xlsx）」）／進捗レポート（赤系タイル・「PDF」）。
  - 中身の一文説明、実際のファイル名プレビュー（等幅、`#F3F4F6` の箱）、「○○をダウンロード」（主、高さ 48px）。
  - 生成中はボタンに「作成中…」＋スピナー、失敗したら `RuleAlert tone="error"` で再試行ボタン。
- ファイル名テンプレート：使える変数のチップ（`{yyMMdd}` `{project}` `{n}`）＋工程表・レポートの入力欄（等幅）＋「チーム固有の記号はそのまま書けます」。入力に合わせてプレビューを即時更新。
- 出力履歴：表（日付・種類・ファイル名・出力した人）。0件のときは点線枠で「まだ出力していません。○/○ が初回の出力になります。」。

### 5-6. モックがない画面（同じ部品・トーンで作る）

- **ログイン `/login`**：中央に白カード（最大幅 400px）。ロゴ、メール、パスワード、「ログイン」。エラーは `Field` のエラー表示。
- **招待受諾 `/invite/[token]`**：「○○さんから『プロジェクト名』に招待されています」＋名前・パスワード設定＋「参加する」。期限切れは「招待の期限が切れています。招待した人にもう一度送ってもらってください。」
- **プロジェクト作成・設定 `/projects`, `/projects/[id]/settings`**：名前、色（6色のスウォッチ、`aria-label` に色名）、アイコン、**締切日（必須）**、**バッファ日数（必須・1以上・稼働日）**、週の最終曜日（既定：金）、ファイル名テンプレート、メンバー招待（メール＋役割）。

## 6. 状態の出し方

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | カード・行の形をしたスケルトン（`#EDEEF1`）。全面スピナーは使わない |
| 0件 | 点線枠の箱＋一文＋次にやる操作のボタン（例：「まだタスクがありません」＋「＋ タスク」） |
| 保存成功 | 右下トースト「保存しました」2秒 |
| 保存不可（R1〜R3） | 入力欄の赤枠＋その場の `RuleAlert tone="error"`。トーストだけで済ませない |
| 警告（R4） | オレンジの `RuleAlert tone="warn"`。保存はできる |
| サーバーエラー | `RuleAlert tone="error"`＋「もう一度試す」 |

## 7. 文言のルール

- 日本語で短く書く。ラベル・ボタンは体言止めか動詞（「進捗を更新」「手を貸す」）、案内とエラーの文はです・ます調で揃える（「保存できません」「空いています」）。
- 日付は `11/19（木）`、期間は `11/17〜11/20`、日数は「n稼働日」。年は年をまたぐときだけ付ける。
- ルール違反の文は「何がダメか」＋「どうすればいいか」をセットにする（例：「成果物を入力してください」「11/24（火）から始める」）。
- 画面に R1〜R5 などの番号は出さない（「成果物」「担当者は1人」「並列なし」「バッファ」「進捗共有」と書く）。

---

## 8. アクセシビリティ

- 押せるものは `<button>` か `<a href>`。`div` に `onClick` を付けない。
- アイコンだけのボタンには `aria-label`。装飾の SVG は `aria-hidden="true"`。
- すべての入力に `<label>`。エラーは `aria-invalid`＋`aria-describedby`。
- タップ領域は 44×44px 以上（表の中の小ボタンは 36px まで可）。
- 文字のコントラストは 4.5:1 以上（§2 の色の組はすべて満たす）。
- キーボードだけで、フィルタ切替・タスク追加・モーダルの開閉・保存ができること。

## 11. 画面の完了条件

- モックの5画面と見た目が揃っている（色・角丸・余白・文字サイズ）。
- 1280px・768px・390px の3幅でレイアウトが崩れない。
- §6 の状態（読み込み中・0件・エラー）が各画面にある。
- キーボードだけで主要操作が完了できる。
- 実装後、各画面のスクリーンショットを3幅分撮って報告に添付する。
