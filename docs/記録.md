### 決めたこと・その理由
| 決めたこと | 理由 |
|---|---|
| Next.js 16 の Cache Components を無効化 | ほぼ全画面がログイン必須で cookie を読む。有効のままだと画面ごとに Suspense の境界が要り、1.5日の開発では手間に見合わない |
| DB ドライバは `@neondatabase/serverless` の Pool（WebSocket） | HTTP ドライバはトランザクションが使えない。R3 の判定と保存を1つのトランザクションでやりたい |
| Neon・Vercel の関数ともにシンガポール（`sin1`） | Vercel の既定はアメリカ東部。DB と離れていると問い合わせのたびに太平洋を往復する |
| 認証は Better Auth を自前の DB に持つ（Neon の Better Auth サービスは使わない） | ユーザー表を tasks などと同じ DB に置き、外部キーでつなぐため |
| PDF 用フォントは Noto Sans JP の TTF（Regular・Bold）を `public/fonts/` に同梱 | @react-pdf/renderer は woff2 を読めない。計画書のリスク表どおり、先に日本語1行で試して文字化けしないことを確認した |
| pnpm 12 で esbuild のインストール処理だけ許可 | 許可しないと shadcn の初期化が失敗する |
| 開発中は Neon の `dev` ブランチを使い、本番は `production` ブランチ | 本番 DB で直接試さないため |

### 起きた問題と対処
- **本番が全ページ 404**：Vercel プロジェクトを空のリポジトリから作ったため、フレームワーク設定が空のままだった。ビルドは成功していたが `public/` しか配信されていなかった。`vercel.json` に `"framework": "nextjs"` を書いて固定した。
- **CI 環境で型チェックが失敗する**：`LayoutProps` などの型は Next.js がビルド時に作る。`typecheck` を `next typegen && tsc --noEmit` にして、先に型を作るようにした。

### 残課題
- 新規登録は誰でもできる。招待した人だけ登録できる制限はタスク5で入れる
- `/api/pdf-test` はタスク11で本実装に置き換えるときに消す
- PR ごとのプレビュー URL では、`BETTER_AUTH_URL` と送信元が違うためログインが弾かれる可能性がある。必要になったら `trustedOrigins` に足す

## 3. DB 設計

- 完了：2026-11-18
- 成果物：`src/db/schema.ts`（アプリ本体の8テーブル）、マイグレーション `0001_app_tables.sql`（自動生成）・`0002_no_parallel_tasks.sql`（R3 の排他制約、手書き）、制約の確認スクリプト `scripts/db-constraint-check.mjs`

### 確認方法
- `pnpm db:migrate` で適用したあと `pnpm db:check`
- 確認スクリプトは1つのトランザクションの中で試してロールバックするので、DB にデータは残らない

### テスト結果
- Neon の `dev` ブランチで `pnpm db:check`：24件成功 / 0件失敗
  - R3：別プロジェクト間の重複・同一プロジェクト内の重複・端の1日だけ重なる・更新で重ねる → すべて拒否。隣接・担当者違い・自分自身の更新 → 通る
  - R0：土日の予定日・実績日 → 拒否。祝日は DB では通る（設計どおり。サーバーで拒否する）
  - R1：成果物が空白だけ・完了なのに URL もメモもない → 拒否
  - R2：担当者なし・プロジェクトのメンバーでない担当者 → 拒否
  - その他：予定開始 > 予定終了、進捗率 101、別プロジェクトのフェーズ、バッファ0日、週の最終曜日が土曜、親のないフェーズ、担当タスクがあるメンバーを外す → すべて拒否。プロジェクト削除で配下がまとめて消える
- 型チェック・lint：成功

### 決めたこと・その理由
| 決めたこと | 理由 |
|---|---|
| 日付列は `date` 型、TypeScript では `"YYYY-MM-DD"` の文字列 | `Date` にするとタイムゾーンで1日ずれる事故が起きる |
| 土日禁止を DB の CHECK にも入れた（`extract(isodow …) < 6`） | 指示書では DB の守りは R3 だけだったが、土日は DB でも判定できるので入れた。祝日は年ごとに変わるので DB では判定せず、サーバーで止める |
| 完了（100%）には成果物 URL かメモが必要、を CHECK に入れた。メモ用に `tasks.completion_note` 列を追加 | R1 の「完了にするには URL かメモが必須」を DB でも守るため。指示書の列一覧にはメモの列がなかった |
| タスクのフェーズと担当者を、複合外部キーで「同じプロジェクトのもの」に限定 | 別プロジェクトのフェーズに付ける・メンバーでない人を担当にする、を DB で防ぐ |
| 担当者の外部キーは `no action`（`restrict` ではない） | `restrict` だと、プロジェクトを消したときの連鎖削除の途中で弾かれる。`no action` は文の最後に判定するので、連鎖削除は通り、担当タスクが残ったままメンバーだけ外すのは防げる |
| 週の最終曜日は 1〜5（ISO 曜日：月=1 … 金=5）に限定 | 週の最終「稼働日」なので、土日は選べない |
| 目的とフェーズの親子関係は CHECK で形だけ守る（目的は親なし、フェーズは親あり） | 「フェーズの親が目的であること」は CHECK では書けないので、サーバーで確認する |
| 招待に `invited_by`、プロジェクトに `updated_at` を追加 | 誰が招待したかを残すため、更新日時を一覧で使うため |
