# マジスケ（マージカルスケジュール）開発計画書

Nov 18, 2026 · @どっかのT

## 背景と目的

身内デベロッパー（少人数の開発仲間）向けのスケジュール管理アプリ「マジスケ（マージカルスケジュール / mergecalschedule）」を作る。複数プロジェクトを横断して、チーム全員のタスクと空き状況を1画面で管理できる。

- 現在、minebook と nomiメモ の2プロジェクトを並行で開発している。
- 既存のスケジュール管理アプリは1プロジェクトまでしか扱えず、プロジェクトをまたいだ担当者の重複が見えない。
- 授業で指定された「WBS作成チェックポイント」5項目を、人の注意ではなくアプリの仕組みで守れるようにする。
- 追加要望として、チームメンバーのタスクをカード形式でひと目で把握できるようにする。

## スコープ

「複数プロジェクトのWBS・ガント・進捗を、ルール違反が起きない形で管理し、週次の提出物まで出せる」ところまでを作る。

| 作るもの | 作らないもの |
| --- | --- |
| 複数プロジェクトの作成・メンバー招待 | チャット機能（Discord等を使う） |
| WBS（目的＞フェーズ＞タスク）の編集 | ファイルストレージ（成果物はリンクURLで紐づける） |
| ガントチャート＋イナズマ線 | 工数・コスト（金額）管理 |
| メンバーカードボード | ネイティブアプリ（PC・スマホのブラウザで使う） |
| WBSルールの自動チェック | 外部カレンダー連携（将来拡張） |
| 工程表（xlsx）・進捗レポート（PDF）の出力 | メール・Push通知（将来拡張） |
| 困りごと（ヘルプ）共有 |  |

初版は11/19に公開するため、ダッシュボードと個人タイムラインは第2版（11/20以降）に回す。

## 機能要件

WBSチェックポイント5項目はすべて「入力時に強制・警告する仕組み」として実装する。特に③並列禁止はプロジェクトをまたいで判定するのがこのアプリの一番の価値。

### WBSルールの実装

| # | ルール | アプリでの実装 | 強さ |
| --- | --- | --- | --- |
| 1 | タスクはスコープ（成果物）単位 | タスク作成時に「成果物」を必須入力。完了にするには成果物のURLかメモが必要 | 保存不可 |
| 2 | 担当者は1人 | 担当者は単一選択・必須。「全員」は選べない。「メンバー分複製」ボタンで人数分のタスクに分割 | 保存不可 |
| 3 | 1人が複数タスクを並列しない | 同じ担当者の予定期間が重なると保存不可。**全プロジェクト横断で判定**。衝突先タスクと「次の空き日」を提示。DBの排他制約でも保証 | 保存不可 |
| 4 | 締切日ぴったりは NG（バッファ） | 締切日とバッファ日数はプロジェクトごとに利用者が入力（あとから変更可、固定値なし）。最終タスク終了日＞締切−バッファなら警告。ガントに「予備期間」の帯を表示 | 警告 |
| 5 | 会議体の設定 | 週の最終曜日を設定すると毎週の進捗共有日を自動表示。その日に工程表（xlsx）と進捗レポート（PDF）を一括出力 | 表示＋出力 |

ルール5の「悩みは早めに共有」は、タスクに「困りごと（ヘルプ）」を出せる機能で支える。出した瞬間にメンバーカードとダッシュボードで目立つ表示にする。「気づけなかったメンバーも悪い」を仕組みで防ぐため。

### メンバーカード（追加要望）

メンバー1人につき1枚のカードを並べ、「誰が今何をやっていて、遅れていないか」を全プロジェクト横断で見せる。

- 表示項目：名前、今日のタスク（プロジェクト色のバッジ付き）、成果物名、進捗率バー、終了予定までの残り日数、次のタスク
- 状態バッジ：順調／遅れ（イナズマ線と同じ判定）／困りごとあり／空き（担当タスクなし）
- フィルタ：全プロジェクト／プロジェクト別。並び順：遅れ・困りごとが先頭
- カードを押すとそのメンバーの担当タスク一覧へ（時系列の個人タイムラインは第2版）
- 自分のカードから進捗率の更新と困りごとの投稿ができる

### その他の主要機能

- **WBS編集**：目的＞フェーズ＞タスクの3階層（授業資料のカレーライス例と同じ形）。並べ替え可
- **ガントチャート**：左にWBS、右に予定バーと実績バー。土日祝はグレー表示
- **イナズマ線**：進捗管理日を選ぶと、各タスクの「予定開始＋期間×進捗率」の位置を結ぶ線を描く。左に曲がれば遅れ、右なら先行
- **マルチプロジェクトダッシュボード（第2版）**：全プロジェクトの進捗率、締切までの日数、バッファ残り、未解決の困りごと件数
- **権限**：プロジェクトごとに「管理者」「メンバー」。管理者はWBSを編集、メンバーは自分のタスクの進捗・実績・困りごとだけ更新
- **出力**：工程表はガント形式の xlsx、進捗レポートはイナズマ線付きガント＋遅延タスク一覧＋困りごと一覧の PDF。ファイル名はプロジェクトごとのテンプレートで自由に設定でき、チーム固有の記号も入れられる（例：`261127b_minebook工程表v1.xlsx`、`261127f_進捗レポート.pdf`）。既定値は {yyMMdd}\_{project}工程表v{n}.xlsx

**稼働日は平日のみ**：土日祝は期間の日数にも進捗計算にも数えず、タスクの開始日・終了日にも選べない。週の最終日の既定は金曜。

## 技術構成

Supabase の無料プロジェクト枠が埋まっているので、DB は Neon（サーバーレス Postgres）を使う。Neon の Free プランは100プロジェクト、1プロジェクトあたり 1GB・月100 CU時間まで無料で、クレジットカード不要（[Neon](https://neon.com/faqs/free-plan-limits-and-quotas)）。Postgres なので「担当者の期間重複禁止」を DB の排他制約で書けるのが決め手。

| 層 | 採用 | 理由 |
| --- | --- | --- |
| フレームワーク | Next.js（App Router）＋TypeScript | 画面とAPIを1リポジトリで書け、Vercelにそのまま載る |
| DB | Neon Postgres（Free） | Supabase枠なし。排他制約（btree\_gist）で並列禁止を保証 |
| ORM | Drizzle ORM＋drizzle-kit | 型安全、マイグレーションをコードで管理、Neonのドライバ対応 |
| 認証 | Better Auth（メール＋パスワード） | ユーザー表を自分のDBに持て、外部認証サービスの枠を消費しない |
| UI | Tailwind CSS＋shadcn/ui | カード・モーダル・表を早く作れる |
| ガント | 自作（CSS Grid＋SVG） | イナズマ線と予備期間の帯を自由に描くため。既製ライブラリは使わない |
| xlsx出力 | ExcelJS | セルの塗りでガントを表現できる。.xlsではなく.xlsx（Excelでそのまま開ける） |
| PDF出力 | @react-pdf/renderer＋Noto Sans JP | サーバーで生成。日本語フォントの埋め込みが必要 |
| テスト | Vitest（ルール判定）＋Playwright（主要導線） | ルール判定は純粋関数にして単体テストを厚く |
| ホスティング | Vercel Hobby | 学生の個人利用なら無料で運用可 |

Neon は5分使われないとコンピュートが停止するので、久しぶりの初回アクセスは数秒遅くなる。運用上は問題ない範囲。

稼働日の判定には日本の祝日データ（@holiday-jp/holiday\_jp）を使う。

## データモデル

タスクは全プロジェクトで1つの `tasks` 表に入れる。だから「同じ担当者の期間重複禁止」をプロジェクト横断で DB が保証できる。認証系の表（user, session 等）は Better Auth が生成するものを使う。

| 表 | 主な列 | 制約・メモ |
| --- | --- | --- |
| `projects` | id, name, color, deadline, buffer\_days, week\_end\_weekday, file\_name\_template | buffer\_days は1以上 |
| `project_members` | project\_id, user\_id, role（owner / member） | (project\_id, user\_id) 一意 |
| `invitations` | project\_id, email, token, expires\_at, accepted\_at | 7日で期限切れ |
| `wbs_nodes` | id, project\_id, parent\_id, level（goal / phase）, name, sort\_order | 目的とフェーズの階層 |
| `tasks` | id, project\_id, phase\_id, name, **deliverable**, **assignee\_id**, planned\_start, planned\_end, actual\_start, actual\_end, progress\_pct, deliverable\_url, sort\_order | deliverable と assignee\_id は NOT NULL。予定開始≦予定終了。progress\_pct は 0〜100 |
| `help_requests` | id, task\_id, user\_id, body, created\_at, resolved\_at, resolved\_by | 未解決 = resolved\_at が NULL |
| `progress_snapshots` | project\_id, status\_date, task\_id, progress\_pct | 週次出力時に保存し、過去のイナズマ線を再現 |
| `exports` | project\_id, status\_date, kind（xlsx / pdf）, file\_name, created\_by, created\_at | 出力履歴 |

並列禁止の排他制約（ルール3）：

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;
ALTER TABLE tasks ADD CONSTRAINT no_parallel_tasks
  EXCLUDE USING gist (
    assignee_id WITH =,
    daterange(planned_start, planned_end, '[]') WITH &&
  );
```

遅れ判定（イナズマ線・カード共通）：進捗管理日における「あるべき進捗率」＝（管理日−予定開始＋1）÷予定日数（どちらも稼働日で数える）。実際の進捗率がこれを下回れば「遅れ」、上回れば「先行」。

## 会議体・リスク・未決事項

### 会議体（この開発自体）

- 2日間の開発なので、区切りは11/18 19:00と、11/19 12:00の2回。その時点でガントに対して遅れているかを確認し、遅れていれば切る機能を決める。
- 公開後は毎週金曜に進捗を口頭で共有し、工程表と進捗レポートをマジスケから出力して提出する（初回 11/20）。
- AIエージェントで詰まったら、30分以上独りで抱えずに共有する。

### リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| PDF の日本語フォント埋め込みで詰まる | 進捗レポートが出せない | 後半にやる前に「日本語1行だけのPDF」を環境構築で先に試す |
| Vercel の関数実行時間内にPDF生成が終わらない | 出力失敗 | 1プロジェクト単位で生成。重ければブラウザ側生成に切替 |
| btree\_gist が使えない／制約エラーが分かりにくい | ルール3の保証が弱くなる | アプリ側でも同じ判定をして日本語のエラーを出す（二重チェック） |
| 自作ガントが想定より重い | 予定超過 | まず表示専用で作り、ドラッグ編集は将来拡張に回す |
| 2日で全機能が終わらない | 作業時間不足 | 予備時間で吸収。足りなければPDF→困りごと→イナズマ線の順に第2版へ |
